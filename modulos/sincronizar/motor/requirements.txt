# Dependências de RUNTIME do sidecar.

# ⛔ A linha `coding` acima NÃO é enfeite: sem ela o pip (até a 24.x, a do venv)
# lê este arquivo na codificação do SO — cp1252 no Windows — e os emojis dos
# comentários têm bytes que o cp1252 não tem (0x8F, 0x90). O `pip install`
# morria com UnicodeDecodeError e derrubava o dev.bat (medido em 2026-09-15).
#
# ⛔⛔ VERSÕES FIXAS (`==`), não `>=` — auditoria de 2026-08-23.
#
# O que estava errado: com `>=`, o `pip install` do workflow de release resolvia o
# que fosse mais NOVO no instante do build, e o PyInstaller empacotava isso no
# `.exe`/`.dmg` que as pessoas baixam. Não havia lockfile, não havia hash, e não
# havia a quarentena de 3 dias que a política de desenvolvimento seguro exige para
# pacote recém-publicado. A cadeia inteira era:
#
#     tag → CI → pip resolve o mais novo → PyInstaller → instalador assinado por
#     ninguém → máquina de quem monta
#
# ⭐ O contraste é o que fecha o caso: o Rust já tinha `Cargo.lock` e o JS já tinha
# `package-lock.json` com integridade sha512 nos 232 pacotes. **Só o Python tinha
# ficado de fora** — o projeto já sabia a prática, faltava aplicá-la aqui.
#
# ⚠️ Isto ainda NÃO é `--require-hashes`, que é o passo seguinte e o certo: pinar a
# versão impede a resolução silenciosa, mas não prova que o artefato baixado é o
# mesmo. Para fechar de vez, gerar com `pip-compile --generate-hashes` e passar
# `--require-hashes` no CI. Registrado como o que falta.
#
# Ao subir uma versão aqui, respeite a quarentena: nada publicado há menos de 3 dias.
